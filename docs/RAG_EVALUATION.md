# RAG 检索评估方法

[运行入口](../eval/README.md) · [综合指标](EVALUATION.md)

## 检索与回答分别检查

检索对照直接请求 kb_ingest 的 /api/v1/knowledge/search，测召回、排序、来源与成本。完整 Agent 通过 Chat HTTP 检查路由、规划、执行、回答和引用。检索命中不代表最终回答正确，不能合并成整体准确率。

本仓库提供通用方法与实现，不分发内部题目、专项语料或实验成绩。使用者需自备原文和来源标注，保持语料、过滤范围与预算一致。

## 对照设计

```text
Dense：向量候选 C → 按向量排序取前 K
Dense＋rerank：相同向量候选 C → 服务端重排 → 前 K
Hybrid＋rerank：向量 C ＋ PostgreSQL 全文 C → RRF 融合成 C → 重排 → 前 K
```

Dense/rerank 应比较相同候选集合，并确认重排实际执行；fallback 不能冒充重排成绩。Hybrid 可独立召回不同材料，但过滤和预算相同。质量、候选覆盖、HTTP 失败、fallback 和耗时分别报告，不挑最快或最高分的一次。

全文使用 PostgreSQL tsvector、GIN、ts_rank_cd，索引与查询端共用 Latin/编号规范化和中文二元组；不是 BM25 或完整中文分词器。RRF 融合名次，不直接相加词法与向量分数。

## 指标

- Recall@K：前 K 位命中的唯一相关文档数 / 所需相关文档数。
- MRR@K：首个相关文档实际名次的倒数，没命中为 0。
- Precision@K：前 K 位唯一相关文档数 / K。
- Candidate recall：重排前候选包含所需来源的比例；重排不能补回未召回资料。
- 无答案题的 Recall/MRR 不适用；相似资料不等于包含答案。
- 重复 chunk 占据实际位置，不增加唯一命中，也不能把 K 外结果补进窗口。
- 耗时保留失败和慢样本，Embedding、召回、全文和重排时间另列。

实现见 [rag_retrieval.py](../eval/evaluators/rag_retrieval.py)。小样本、单轮观测不能证明泛化收益或生产 SLA；不能因实现 Hybrid 就假设它必然更好。

## 原文、身份与过滤

原文是 Evidence 的依据，辅助改写不能替代政策来源。domain/dataset_id/source_id 应稳定且可核对，版本、日期、适用范围由来源提供。--corpus 必须与已摄取记录一致，完整性不符就停止。

向量和全文共享过滤范围；模式、域和日期来自显式上下文，不按问题关键词猜。Chat 不提供任意知识域切换接口；非默认产品域问题应使用检索模式，不能把其结果冒充 Chat 测量。

## 接受门槛与回答

排序分数不是答案概率。用独立开发问题比较漏召回和错误放行，再检查留出回归；测试组不参与选择。共享文档或已知失败回归不等于盲测。更换语料或模型后需要重新校准，不能照搬其他实验结论。

回答另查引用可解析、预期来源被引用、引用 Evidence 的声明事实及无答案拒答。有限字面规则仍可能漏掉否定、条件、矛盾或额外声明，需要人工语义复核。

## 自备输入运行

命令和 JSONL 字段见[Runner 说明](../eval/README.md)。显式指定 --dataset 与 --corpus，并先用现有摄取接口准备隔离语料。公开版本不分发内部专项初始化脚本，不应覆盖产品域或历史记录。
