# 安全整改与发布验证

2026-11-05，本轮仅收口既有 Data Agent 的安全边界，不增加 Agent、工具或模型能力。

## 已落地边界

- 应用持久化使用 `APP_DATABASE_URL`；Text2SQL 只使用显式 `BUSINESS_DATABASE_URL`，不回退应用库。业务 schema/table 白名单、实际只读 GRANTS 检查、数据库事务只读与原有 SQL 校验共同生效。
- Chat、Session、History、Upload 以短期 JWT 的签名 `sub` 验证身份及 owner；请求不能更换 Session 所有人。身份比较区分大小写与尾部空格，不继承数据库默认排序规则的宽松比较。知识服务使用独立内部服务令牌。
- CORS 使用配置的明确来源，缺省不放行跨域，不允许通配符来源。
- 客户端错误只保留安全类别、提示与 trace_id；不回显内部异常和校验输入。
- 上传和原始请求体均限制大小；文件名由服务端生成，以有归属的 file_id 查找受控目录。已上传文件确定性进入文件处理，不调用 LLM 分类。
- SSE 表达 progress/final/error/done，不模拟 token 流；最终消息先保存到聊天历史，断开连接时取消执行。多工具部分失败时，回答上下文和确定性回退也不回显原始工具异常。

## 升级与限制

按[部署说明](DEPLOYMENT.md#安全发布配置与升级)配置两个独立数据库账号、随机签名密钥和内部服务令牌。已有数据库、owner 为空的历史 Session、旧上传记录不会自动迁移或认领；没有 owner 的旧记录不能匿名访问。新上传必须使用 file_id。

本轮未执行需要真实 LLM、Embedding、Reranker 的完整问答 Smoke，不将 Mock 或基础设施验证描述为真实模型验证。JWT 仍是最小身份验证能力，不是完整用户管理、RBAC、业务数据租户/行级权限或令牌撤销平台；生产仍需 HTTPS、可信身份签发、密钥轮换和流量控制。保留已有弃用警告，不通过屏蔽警告或删除测试制造通过结果。
